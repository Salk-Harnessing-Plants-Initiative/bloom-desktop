## Why

CylinderScan's packaging CI has never exercised the actual deployment path. CI runs `npm run package` but never `npm run make`, so the DMG/Squirrel/deb maker stage — the thing that actually produces the installer lab machines will run — is completely unverified (#251). The one packaged-app smoke test that exists (`test-package-database`) only runs on `macos-latest`, even though the real deployment target is Windows lab machines (#57). Separately, the CylinderScan hardware validation docs (Basler camera + NI-DAQ) were written early in development and have drifted from the current code — stale defaults, a documented setting that no longer exists, and undocumented real features — which would mislead anyone using them ahead of the physical Windows rollout (#180).

This tier has no dependency on any other CylinderScan tier and can run in parallel with all of them.

## What Changes

- Add a new `test-make` CI job (macOS) that runs `npm run make` end-to-end: asserts the DMG/ZIP maker artifacts are actually produced under `out/make/`, then launches the staged app binary and asserts (a) a real window renders and (b) the database initializes correctly. This closes #251's specific "no assertion that a window actually renders, not just a DB log line" gap; it does **not** close #251's separate, broader ask for a Playwright smoke run that exercises renderer/IPC behavior inside the packaged app (asar/resource-path regressions) — that remains open, see design.md non-goals. The existing `test-package-database` (macOS, `npm run package`) job is left unchanged as the fast baseline smoke test.
- Add a new `test-make-windows` CI job that runs `npm run make` on `windows-latest`, asserting the Squirrel installer artifacts are produced and performing the same window-render + DB-init verification as the macOS make job. This is CylinderScan's first Windows packaged-app verification, satisfying #57's Windows-coverage ask and #251's Windows-installer-equivalent-smoke-test ask in one job. Linux is explicitly out of scope for this change (see design.md non-goals; GraviScan's own Linux packaging-CI equivalent is tracked separately, see below).
- Both new jobs upload their verified `out/make/**` artifacts as downloadable CI build artifacts (7-day retention) once verification passes, so the actual DMG/Squirrel installers can be picked up for manual test-installation (e.g. ahead of Tier 5b's hardware QA) rather than only being built-then-discarded inside the CI run.
- Introduce two new cross-platform TypeScript integration scripts (`tests/integration/test-make-artifacts.ts`, `tests/integration/test-packaged-app-launch.ts`) plus small extracted helper modules, using Playwright's Electron driver and `better-sqlite3`, rather than extending the macOS/Linux-only bash script (`scripts/test-package-database-full.sh`) with Windows branches. This is a new usage pattern for this repo (launching a _packaged_ binary via Playwright, not the dev build) — see design.md Decisions 2 and 2a for the required `ELECTRON_RUN_AS_NODE` mitigation this repo has already needed once before.
- Fix documentation drift in `docs/CAMERA_TESTING.md`, `docs/DAQ_TESTING.md`, `docs/SCANNER_TESTING.md`, `docs/CONFIGURATION.md`, and `.claude/commands/hardware-testing.md` so they match already-accepted OpenSpec requirements (`machine-configuration`'s camera-compatibility and scan-parameter specs, `scanning`'s metadata.json field spec, `developer-workflows`' hardware-testing-command spec) — no `brightness`/`contrast` field in `CameraSettings`, correct `gain` type/range/default, correct `seconds_per_rot` default, correct camera-settings shape, `metadata.json`/`ScanMetadata` coverage (including that `metadata.json` legitimately still writes fixed `brightness: 0`/`contrast: 0` values — the docs must not claim these are absent from that file).
- Document previously-undocumented real features with no existing doc coverage: scanner identity service, idle-session-reset behavior, and `experiment_type`.
- Create `docs/TROUBLESHOOTING.md` consolidating troubleshooting steps currently scattered across the hardware docs.
- Re-wire the orphaned `tests/integration/test-camera.ts` to a new `test:camera:connect` script (distinct coverage from `test:camera`'s streaming test — not deleted), and update `developer-workflows`' "Integration Testing Command" requirement to document it.
