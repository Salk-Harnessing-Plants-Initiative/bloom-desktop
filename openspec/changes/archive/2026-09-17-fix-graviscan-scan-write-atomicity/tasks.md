## 12. Review round 5 (five-lens subagent team, 2026-09-16)

Round 5 ran five parallel lenses after round 4 had declared convergence. It found **three blocking issues**, one of them independently by three lenses. Recorded here because "four rounds converged" turned out not to mean converged.

- [x] 12.1 **B3 — a failing `fsync` was swallowed and the file published anyway.** The pre-rename durability check wrapped both the temp-file reopen and `os.fsync` in one `except OSError: log(); continue`, then called `os.replace()` regardless. Those are different failures: a failed reopen means "could not verify", a failed fsync means the bytes never reached storage — and on ext4 with delayed allocation ENOSPC/EIO surface at fsync, not at close. Publishing then put a short or zero-filled TIFF at the canonical timepoint filename, the exact corruption this change exists to prevent, reached by a different route than SIGKILL. Note this **reverses part of 7.8**, which had made the whole block best-effort: that was right for the reopen and wrong for the sync. Now split, with the fsync propagating into `_sane_scan()`'s retry loop. TDD: three new tests written red first (fails the write, publishes nothing, does not clobber a pre-existing good file).
- [x] 12.2 **B1 — a late `scan-complete` from an earlier cycle was counted as the current cycle's.** The 7.11 cross-row guard keys on `plate_index` alone, which separates rows _within_ a cycle but not cycle N's row `['00']` from cycle N+1's — and with one row group per cycle it discriminates nothing. A row timeout does not abort the worker, so the stale completion was verified against the earlier cycle's real file and logged as `1/1 files verified` for a cycle that scanned nothing. Reproduced red before the fix. Now discriminated by the `_cy<N>_` token, armed only when the dispatched basename carries one so a token-less scheme degrades rather than dropping every event.
- [x] 12.3 **B2 — every `exit` in the coordinator tests used a payload production never emits.** All seven sites emitted `{}` where `ScannerSubprocess` emits `{ scannerId, code, signal }`; the coordinator evicts a dead subprocess by `info.scannerId`, so the identity-guarded lookup missed and tests kept dispatching rows to a subprocess production had already removed. The same defect class as 7.5 (`exp_name`) and round 1's `removeAllListeners`. Fixing the payload exposed a real gap — after a worker dies, later row groups dispatch nothing and logged nothing at plate level — closed by an end-of-row reconciliation of `platesPerScanner` against the scanners that actually received the row. This also closed the USB-stagger skip (7.7), which took the same silent path.
