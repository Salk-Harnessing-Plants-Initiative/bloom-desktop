## Why

CylinderScan has drifted from the visual style of `bloom-desktop-pilot`, the retired app it's migrating from and is still expected to match — blue/indigo accents remain across several files even though the pilot's actual palette (verified directly from its source) is lime/stone/amber, and `CameraSettings.tsx` lacks the centered `max-w-7xl` container every other primary page uses (a pending, unmerged OpenSpec change already targets this in isolation). Separately, the Home page's workflow guide conflates one-time admin setup with the daily scanning workflow, buries the primary "Capture Scan" action at step 6, and gives operators no at-a-glance view of today's activity or upload health (#104, #175); and BrowseScans' table is missing a thumbnail preview and camera-settings visibility per scan (#106/#107).

This is Tier 4 of the CylinderScan finalization roadmap (`docs/superpowers/plans/2026-08-03-cylinderscan-finalization-roadmap.md`) — a style/UX parity pass with no dependency on any other _CylinderScan_ tier. This revision was rewritten after reading the actual text of GitHub issues #104/#175/#106/#107 directly (the initial draft worked from a roadmap-doc paraphrase that understated their real scope) and after three rounds of 5-lens pre-implementation review — see `design.md`'s "Revision history" for what changed and why.

**Scope note:** two unrelated, in-flight GraviScan PRs (#289, #290) actively rewrite `Layout.tsx` and `WorkflowSteps.tsx`'s `graviScanSteps` path. Rather than wait for them to merge, this change **defers** the `Layout.tsx` shell/sidebar recolor and the `graviScanSteps` structural restructure to a follow-up (tracked in a new GitHub issue), and makes zero edits to either PR's actively-changing code paths. See `design.md`'s "Deferred Scope" for the exact boundary.

## What Changes

- **Fold in the pending `align-page-layout-centering` change.** `CameraSettings.tsx`'s root container (currently plain `p-8`, no width constraint) adopts the same `min-h-screen bg-gray-50 p-6` + `max-w-7xl mx-auto space-y-6` pattern as `CaptureScan.tsx`, with panel shadows normalized from `shadow` to `shadow-sm`. The standalone pending change (`openspec/changes/align-page-layout-centering/`) is deleted — its scope is fully absorbed here.
- **Blue/indigo → lime/stone/amber accent sweep**, using a color mapping adapted from the pilot's verified real usage to bloom-desktop's existing interaction conventions (shade-darkening hover, shade-change link hover, a new `focus:ring-lime-500`). See `design.md` for the full mapping and rationale.
  - CylinderScan-only files (zero GraviScan impact): `CaptureScan.tsx`, `ExperimentChooser.tsx`, `PhenotyperChooser.tsx`, `PythonStatus.tsx`'s "Check Hardware" button, `Accessions.tsx`, `AccessionForm.tsx`, `AccessionList.tsx`, `AccessionFileUpload.tsx`.
  - Shared, both-mode files (recolor applies cross-mode, functionally identical): `BrowseScans.tsx`, `ScanPreview.tsx`, `ExperimentForm.tsx`, `PhenotyperForm.tsx`, `ScientistForm.tsx`, `MachineConfiguration.tsx`.
  - **Deferred (not in this change):** `Layout.tsx`'s root background and sidebar nav-link active/hover state — both PRs above are actively rewriting this file. See `design.md`'s "Deferred Scope."
  - **Explicitly out of scope:** `CaptureScan.tsx`'s green "Start Scan" button/success banner (stays green), `ConfigureScanner.tsx` (GraviScan-only page), and any gray-tone chrome beyond `Layout.tsx` (deferred, not a general precedent elsewhere).
- **#104/#175 — Home page workflow guide and status dashboard**, redesigned per the actual issue text (not a content-only refresh), **scoped to CylinderScan only in this change**:
  - A new, dedicated `CylinderScanWorkflowGuide.tsx` component (not a change to the shared `WorkflowSteps.tsx`) implements the two-section structure #175 asks for — **Daily Workflow** (prominent, no step numbers: Camera Settings, Capture Scan as a large primary CTA, Browse Scans) and **Setup** (less prominent, unordered cards, no step numbers: Scientists, Phenotypers, Accessions, Experiments). `cylinderScanSteps` moves out of `WorkflowSteps.tsx` into this new component; `WorkflowSteps.tsx` itself, `graviScanSteps`, and GraviScan's rendering are **completely untouched** — #175's "applies to both modes" text is real, but applying the same restructure to `graviScanSteps` is deferred (see `design.md`) rather than built against a file #290 is actively rewriting.
  - Home page adds a "Today's Activity" summary: today's captured scans (date, plant ID, experiment) and an upload-status count breakdown (pending/failed/uploaded), aggregated via a new low-level `countUploadStatuses()` helper (extracted alongside, not instead of, `BrowseScans.tsx`'s existing per-scan status label — see `design.md`). Reuses the existing `db:scans:getRecent` IPC call (today-scoped, as it already behaves for `CaptureScan.tsx`'s own recent-scans widget), extended to also select each image's `status`.
  - Separately, a persistent "N failed uploads need attention" indicator (linking to Browse Scans) surfaces whenever **any** upload has failed, regardless of date — a new, small `db:scans:getFailedUploadCount` IPC handler (a single count query), since #104's "needing attention" framing shouldn't disappear just because nothing was captured today.
  - `PythonStatus.tsx`'s hardware-unavailable state shows "Contact your administrator" copy (no link to Machine Configuration, which is intentionally admin-only) — confirmed no such link exists today, and this adds an explicit regression-guard test to keep it that way.
- **#106/#107 — BrowseScans.tsx table additions.**
  - Thumbnail-preview column (48×64px): lazy-loads (`loading="lazy"`) each scan's lowest-`frame_number` image via the existing `bloom-scan://` protocol + `pathToFileUrl()` — no new protocol/IPC handler.
  - Camera-settings column: a compact summary including Scanner Name/Device (e.g. "Cam-A · Exp 50000μs · Gain 4" — `exposure_time` is stored in microseconds, not milliseconds; corrected during post-implementation review after the first pass mislabeled it "ms") with the full field set (scanner name, exposure, gain, brightness, contrast, gamma, seconds-per-rotation) available via a `title` tooltip on hover — chosen over dedicated always-visible columns or a column-configuration UI (both suggested as alternatives in #107) specifically to satisfy the issue's "table remains readable without horizontal scrolling" acceptance criterion.
  - `db:scans:list`'s paginated query (`src/main/database-handlers.ts`) extends its `images` select from `{ id, status }` to `{ id, status, path, frame_number }`.

## Impact

- **Affected specs:**
  - `ui-layout` (new capability) — absorbs the pending `align-page-layout-centering` change's "Camera Settings Page Layout" requirement.
  - `ui-color-palette` (new capability) — the lime/stone/amber accent convention, now including `Accessions.tsx`'s subcomponents, the three shared entity forms, and `MachineConfiguration.tsx`. Does **not** include `Layout.tsx` (deferred).

- **Removed:** `openspec/changes/align-page-layout-centering/` (superseded).
- **Zero GraviScan impact by construction, not just by testing:** GraviScan's rendering code path (`Layout.tsx`, `WorkflowSteps.tsx`'s `graviScanSteps` branch) is not touched by any file this change edits — narrower than earlier revisions' "intentional cross-mode change, verified by tests" approach, adopted specifically because #289/#290 are actively rewriting those files.
- **Coordination note:** Tier 2 (delete/upload data-integrity, running in a separate worktree) may also touch `BrowseScans.tsx`'s delete-affordance region. This change's edits target disjoint regions — see `design.md`'s pre-merge diff-check plan.
- **Deliberately out of scope (see `design.md` for full issue-vs-scope accounting):** #175's "optional enhancements" (a session checklist) — explicitly marked optional in the issue text; a column-configuration UI for #107 (the compact-summary approach was chosen instead); `Layout.tsx`'s shell/sidebar recolor and `graviScanSteps`'s structural restructure — **deferred to a follow-up issue**, not abandoned, due to active concurrent edits from #289/#290.
- **Risk:** Low. One new, small, read-only IPC handler (`db:scans:getFailedUploadCount`); no schema changes; no behavior changes to scan capture/upload/delete; zero edits to the two files two other in-flight PRs are actively rewriting.
