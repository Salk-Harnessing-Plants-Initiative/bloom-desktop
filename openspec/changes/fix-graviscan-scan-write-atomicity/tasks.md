## 6. Review round 1 follow-ups (subagent review team, 2026-09-11)

Five parallel reviewers found four blocking issues and nine important ones. Everything below is fixed on this branch; the reviewers' full write-up is posted on the PR.

- [x] 6.1 **B1** — `stopScanner()` strips the subprocess's listeners before awaiting shutdown, so the `exit` listener the row promise registered could never fire. The per-plate diagnostic therefore never ran on the wedge-auto-pause path it was designed for, and every wedge stalled the whole row for the full 90s `SCAN_ROW_TIMEOUT_MS` behind `Promise.all`. Added a `stopped` outcome that `stopScanner()` settles explicitly before stripping listeners. Test written first: "diagnoses a row that stopScanner() ended mid-flight (the wedge auto-pause path) without waiting out the row timeout" — it advances only 5s of fake time, so it fails if the row still needs the timeout.
- [x] 6.2 **B1 root cause in the suite** — `createMockSubprocess`'s `removeAllListeners` was `vi.fn().mockReturnThis()`, a no-op that kept listeners alive and let tests settle rows via a path production cannot take. Now delegates to the real `EventEmitter` implementation. All 55 pre-existing tests still pass against the faithful mock.
- [x] 6.3 **B2** — the exit outcome discarded the `outputPaths` accumulated from plates that had already completed, so a known-good plate was logged as "output presence unknown", skipped its on-disk verification, and was undercounted in the grid tally. All outcomes now carry both the plates asked for and the paths that arrived; the diagnostic covers only plates that never reported. Test written first: "verifies plates that already reported a path before the exit, and diagnoses only the unreported ones".
- [x] 6.4 **B3** — the spec delta's retained scenario bullet "no rename operation SHALL occur after save" contradicted the `os.replace()` this change introduces, and `openspec archive` would have written that contradiction into the canonical `scanning` spec. Reworded to scope it to a rename to a _different final path_.
- [x] 6.5 **B4** — the load-bearing SIGKILL test slept a guessed 1.5s and asserted only absence, so it passed identically whether the kill landed mid-write or before the write began. Two reviewers proved it vacuous empirically (temp file appears at t=0.64-1.09s; a kill at 0.3s still passed every assertion). Now polls for the temp file's real appearance, asserts it exists before killing, and asserts the residue remains afterward. 5/5 stable and faster than the version it replaces (0.86s vs ~1.7s). Also documents that `glob()` skipping dotfiles is load-bearing in the final assertion.
- [x] 6.6 **I1** — `_atomic_image_save()` leaked its temp file on every _handled_ failure, multiplied by `_sane_scan()`'s five retries with a fresh name each attempt. Added `try/except` cleanup that never masks the original exception. Updated the existing test that asserted the leak (`assert len(leftovers) == 1`) to assert the fix, and added the rename-failure case.
- [x] 6.7 **I2** — `GRAVISCAN_TEST_SLOW_WRITE_MS` was unvalidated, unbounded, and live in the real SANE write path (reachable because `buildSubprocessEnv()` spreads the whole main-process environment into the worker). Was made mock-gated, defensively parsed and clamped here; superseded by 8.2, which removed the hook altogether after proving it never executed at its only consumer.
- [x] 6.8 **I3** — removed the per-iteration `!this.cancelled` guard. design.md claimed it was unreachable and used that to skip testing it; it is in fact reachable, because the loop `await`s filesystem checks inside the same body, so a cancel landing on one row's `await` suppressed a different row's already-determined diagnostic depending only on array order. design.md corrected and a test added for the interleaving.
- [x] 6.9 **I4** — the `.tmp-` prefix was a bare literal duplicated across the language boundary (inlined twice on the TS side). Now `TMP_PREFIX` / `GRAVISCAN_TMP_PREFIX`, with a drift-guard test that reads the Python literal back out of the source and fails on a one-sided rename.
- [x] 6.10 **I5** — the diagnostic carried only a scanner UUID, cycle, and two-digit grid index, which does not meet design.md's own "self-sufficient to reconstruct later" standard. Now includes experiment name, wave number, and the expected output directory. Also fixed the latent trap the reviewer flagged: the outcome captured `rowPlates` (stale `_st_` timestamp and cycle) rather than the corrected `platesToScan`.
- [x] 6.11 **I6** — added an `fsync` of the temp file before the rename, plus a best-effort directory `fsync` after it, so the guarantee extends past process kill to power loss. Test asserts the fsync/replace ordering, not just the end state.
- [x] 6.12 **I7** — `grid-complete` logged a bare count, making 4-of-4 and 4-of-5 indistinguishable. Now logs `K/M files verified` with an explicit `MISSING` marker on a shortfall.
- [x] 6.13 **Environment, not a defect** — four unit test _files_ failed to collect in this worktree (`@prisma/client did not initialize yet`) because `prisma generate` had not been run here. Ran it; `tsc --noEmit` is now fully clean, which also retires the "pre-existing Prisma-generated-type errors" caveat from 5.2.

## 7. Review round 2 follow-ups (subagent review team, 2026-09-11)

Round 2 re-reviewed the round-1 fixes. It confirmed B2, B3, B4, I1, I2, I4, I6, I7, I8, I9 and the mock-fidelity change as correct and complete (several mutation-tested, not eyeballed), and found that the round-1 work was incomplete on one path and had introduced one regression. All fixed here; each fix below is mutation-verified — the stated mutation was applied, the named test observed failing, and the source restored.

- [x] 7.1 **R2-B1** — `shutdown()` had the identical listener-stripping defect `stopScanner()` was fixed for, and it is the Cancel Scan path (`cancelScan` calls `cancelAll()` then `shutdown()` in the same tick; `cancelAll()` only writes to stdin, which a blocked worker cannot read). Orphaned rows stalled 90s and then emitted a spurious row-timeout `scan-error` for a deliberately cancelled scan. `shutdown()` now settles in-flight rows first. Traced the other teardown paths: `killAll()` does not strip listeners (rows settle via `exit`) and `reclaimUnresponsive()` only runs for a spawn that never became ready, so neither needs the treatment. Mutation-verified: removing the settler call fails "settles in-flight rows when shutdown() strips listeners".
- [x] 7.2 **R2-B2** — `inFlightRowSettlers.delete()` was unguarded by identity, so an orphaned row settling late could delete a _live_ row's settler and silently restore the round-1 gap. Now identity-guarded, matching `spawnInFlight`'s existing convention in the same file. Defense-in-depth: 7.1 removes the mechanism that produced orphans in the first place.
- [x] 7.3 **R2-B3** — the `K/M` tally derived its denominator from dispatched `results`, so a scanner removed mid-cycle shrank **both** sides and a short grid logged as `3/3 files verified` — an affirmative completeness claim that is false, and strictly worse than the bare count it replaced, which claimed nothing. The denominator now comes from `platesPerScanner` (what the cycle was asked to scan). Mutation-verified: reverting to the results-based sum fails "keeps the expected denominator honest when a scanner is stopped mid-cycle".
- [x] 7.4 **R2-B4** — the round-1 grid-tally test asserted only `/\d+\/\d+ files verified/`, a shape not a value; mutation testing showed both `const expected = 0` and deleting the `MISSING` marker survived it. It now asserts the real numbers (`0/1 files verified`, `1 MISSING`) for a known-short grid.
- [x] 7.5 **R2-I1** — the `exp_name` context added in round 1 was dead in production: `PlateConfig.exp_name` is optional and nothing in `src/` populates it (the renderer's plate builder at `useScanSession.ts:888` does not), so every line would have read `experiment unknown-exp`. The round-1 test passed only because the fixture was edited to inject it. Rather than plumb the name through, the field is dropped and the line now quotes the full cycle-corrected expected path, which encodes experiment id, wave, scanner and cycle. The fixture injection was removed so `makePlatesMap` matches the real IPC shape again.
- [x] 7.6 **R2-I2** — verification now runs for `timeout` rows (a round-1 change), which could emit a _second_ `scan-error` for a row that already emitted its row-level one; two coordinator `scan-error`s trip `WedgeDetector`'s `consecutive_failures` and auto-pause a merely-slow scanner. Verification failures on a timed-out row are now logged only. Spec updated so the two scenarios added last round no longer contradict each other. Mutation-verified: removing the suppression fails "does not emit a second scan-error while verifying a row that already timed out".
- [x] 7.7 **R2-I3** — `stopScanner()` during the USB-stagger window still hung the row for 90s, because the row promise (and therefore its settler) does not exist until after the stagger `await`. The loop now re-checks subprocess identity after the stagger and skips a stopped scanner with a log line. Mutation-verified: disabling the check fails "skips a scanner stopped during the USB stagger window".
- [x] 7.8 **R2-I4** — the fsync sat inside the `try`, so a filesystem refusing the reopen/sync (or a transient Windows AV lock) would unlink a fully-written temp file and fail the plate after five full-resolution rescans. It is now best-effort and logged, matching the directory fsync's treatment: atomicity comes from temp-then-replace, and refusing to publish a good image because durability could not be confirmed is a worse trade. Spec bullet reworded from "SHALL be flushed" to "SHALL attempt to flush", with the fallback stated.
- [x] 7.9 **R2-I5** — added the missing coverage round 2 found by mutation: a `KeyboardInterrupt` test locking in `except BaseException` (narrowing to `except Exception` previously broke no test, though the widening is load-bearing), a failing-fsync test, a later-cycle test proving the diagnostic quotes `_cy2_` rather than the stale `_cy1_`, and a two-scanner test for the spec's "the remaining scanners' rows SHALL proceed without additional delay", which the round-1 single-scanner test never exercised. Corrected the `platesToScan` comment, which claimed the line reports a cycle while the message logged only `dirname` — it now logs the full path, so the claim is true and tested.
- [x] 7.10 **R2-I6** — roadmap left internally inconsistent by the round-1 edit: #361's bullet still said "three items" while the others said five. All counts now agree.
- [x] 7.11 Suggestions taken: `onScanComplete` now ignores plates outside this row (a timed-out row's late `scan-complete` was landing on the next row's listener and counting against the wrong grid) and dedupes repeat events, both of which protect the now-load-bearing tally; `design.md` Decision 2 rewritten to describe the shipped tagged record rather than the two-revisions-old union; the `""` case in the non-numeric parametrize replaced with `"12x"`, since the empty string short-circuits before `int()` and passed for a different reason than its name claimed.

## 8. Review round 3 follow-ups (subagent review team, 2026-09-11)

Round 3 ran two reviewers to test for convergence. The correctness reviewer traced all eight round-2 fixes and returned **CONVERGED**, having specifically hunted the three regressions the fixes could plausibly have introduced (the `rowGrids` filter silently dropping a legitimate plate, the stagger `continue` corrupting bookkeeping, the new denominator manufacturing a false shortfall) and found none real. The testing reviewer ran a **33-mutation sweep** and returned **NOT CONVERGED** on test-discipline grounds, not behaviour. Its surviving mutants are fixed here.

- [x] 8.1 **F1 — a spec `SHALL` clause was unasserted.** "Plates that reported a path before the row ended are still verified … AND each such plate SHALL count toward its grid's verified tally": gating the `verifiedByGrid` increment on `kind === 'done'` passed 66/66. The existing test's own comment named the harm ("undercount it in the grid-complete tally") and then never checked it — the identical defect class rounds 1 and 2 both hit. Now asserts `1/1 files verified` with no `MISSING` for the completed plate. Mutation-verified.
- [x] 8.2 **F2/F3 — removed the `GRAVISCAN_TEST_SLOW_WRITE_MS` hook entirely.** Instrumentation showed the SIGKILL test's poll always won the race, detecting the temp file at 0.66-0.76s _while `image.save()` was still writing_, so the hook was never reached at its only consumer. Two mutants proved it: moving the hook after `os.replace` survived, and the `mock=` gate at the `_sane_scan` call site could be flipped to `True` without failing anything CI runs (both `_sane_scan` tests are `@pytest.mark.hardware` and deselected there). Rather than add tests for a seam that bought nothing, the hook, its constant, its `mock=` plumbing and its six unit tests are gone — which also removes environment-readable code from the live SANE write path, the concern round 1 raised as I2. The test's docstring now describes the window it actually exercises (a kill inside `image.save()`, the stronger case and the one #281 describes) and points at the ordering unit test for the complementary post-save window. 8/8 stable at ~0.95s.
- [x] 8.3 **F4 — three round-2 guards had no test.** The `rowGrids.includes(...)` cross-row filter and the `outputPaths` dedupe now have one: a 4grid row that receives a duplicate plate `00` and a stray plate `10` belonging to the next row group must verify neither and must still log `1/1`. Both mutants are now caught. The `inFlightRowSettlers` identity guard remains untested — it is defense-in-depth whose triggering mechanism 7.1 removed, and constructing the interleaving requires an orphaned row that can no longer occur; noted rather than papered over.
- [x] 8.4 Documentation accuracy, the recurring failure mode in this change. `proposal.md` still claimed the diagnostic carries "experiment" and an "output directory" (both superseded by 7.5's full-path form) and described the `fsync` as unconditional after 7.8 made it best-effort; `design.md` still said `_atomic_image_save()` "does not catch" a rename failure after 6.6 made it clean up and re-raise. All corrected. The spec's tally scenario now pins _where_ the denominator comes from — previously a revert to the results-derived sum (the exact R2-B3 bug) would still have satisfied the spec text, with only the unit test holding the line.
- [x] 8.5 Added a spec scenario for the cross-row/duplicate completion guard, which was shipped behaviour with no requirement behind it.

**Known, accepted after three rounds:** `python/graviscan/scan_worker.py` is in the coverage `omit` list, so the atomic-write helper contributes nothing toward the 80% gate despite being a data-integrity primitive; and `_sane_scan()`'s own tests are hardware-marked and deselected in CI, so the real (non-mock) write path has no automated coverage there. Both pre-date this change and are worth a follow-up, but neither is introduced here.
